# Financial Dashboard A/B Test — Feature Rollout Experiment

[![CI](https://github.com/rmendoza5418/financial-dashboard-ab-test/actions/workflows/ci.yml/badge.svg)](https://github.com/rmendoza5418/financial-dashboard-ab-test/actions/workflows/ci.yml)

> **Simulated data.** Every dataset and result in this repository is synthetic and generated by `data/generate_data.py`. The scenario is hypothetical, not a real firm or study.

A controlled experiment measuring the impact of a redesigned account summary dashboard on client engagement in a financial services context.

## Business Problem

In this hypothetical scenario, a wealth management firm redesigned its primary account summary dashboard (the first screen advisors see after login) to surface actionable alerts, YoY performance comparisons, and client-at-risk indicators. Before rolling out to all 2,400 advisors, the BI team ran a controlled experiment to validate that the new design actually improved engagement and didn't introduce unintended friction.

## Experiment Design

| Parameter | Value |
|---|---|
| Unit of randomization | Individual advisor |
| Control | Existing account summary dashboard |
| Treatment | Redesigned dashboard with alert surfacing + YoY comparisons |
| Primary metric | Daily Active Rate (% of assigned advisors who opened the dashboard on a given day) |
| Secondary metrics | Avg. session duration, client profile drill-down rate |
| Guardrail metric | Error rate (one-sided test) |
| Sample size | 1,200 per arm |
| Duration | 28 days |
| Statistical design | Welch t-test on advisor-level means with bootstrap 95% CIs, α = 0.05; Benjamini-Hochberg correction for subgroup analysis |

## Why This Matters for BI Teams

Dashboard redesigns in financial services are high-stakes: advisors have tight workflows and low tolerance for friction. A BI team that ships a new dashboard without measuring adoption impact is flying blind. This experiment shows how to:

- Design a valid randomized experiment within an existing BI platform
- Choose the right unit of randomization (advisor, not session)
- Separate signal from noise when usage patterns are seasonal (week-of-month effects in wealth management)
- Present results in a format that drives a clear go/no-go decision

## Results Summary (synthetic data)

On the generated dataset (seed 99), the redesigned dashboard drove a **+9.5pp** lift in daily active rate (+18.1%, 95% CI: [8.6pp, 10.3pp]), about **+32 seconds** in average session duration, and a **+8.1%** lift in client profile drill-down rate. The error-rate guardrail failed: errors rose **+37.8%** (p = 0.002). The decision framework therefore returns **HOLD**, not a rollout. The point of the exercise is that a strong engagement lift does not override a failed guardrail.

## Key Concepts Demonstrated

- Week-of-month detrending for financial services data (usage spikes at month-end)
- Subgroup analysis with multiple comparison correction (Benjamini-Hochberg)
- Practical significance vs. statistical significance — what lift actually justifies a rollout
- Communicating uncertainty to non-technical stakeholders (CI interpretation)
- Guardrail metric monitoring — how to know when to stop an experiment early
